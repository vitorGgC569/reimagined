## Frozen small corpus

L6: the first five events contain three WRITEs to distinct entities and two NOOP
entity-id distractors in shuffled order. The final event is one QUERY for a
written entity. Entity ids and observed values are 0..3. No overwrites, missing
binding, revocation, group operator or additional query occurs in generated data.

The numeric row is exactly eight floats: one-hot entity4 followed by one-hot
value4 on WRITE only. NOOP/QUERY have a zero value block and only current id.
NOOP and QUERY for the same entity have identical numeric rows. The current
write/read distinction comes from causal routing metadata. There is no query
answer, target, sample seed, split id, future value or solver feature in x/control.

Targets are length6: -100 for the first five events and raw class0..3 for the
final query. There are exactly four readout classes and no generated undefined
class. This differs from frozen P0 INST's undefined125/compact5 convention.

The namespace is `P1fresh-MQAR-positive-v1`. SHA-derived 128-bit data seeds include
namespace, model seed, split, sample and attempt. Model paired seeds remain
11,23,37,53,71. Per model seed:64train/32validation/64test,160examples; total800.
Seed/split namespaces are separate. No P0 derived data seed is reused (checked
against the old pinned corpus); old datasets are not imported into P1 training.

Observable duplicates are rejected globally across all15files/800examples using
SHA of numeric x, current control and query mask. Target/provenance cannot make
a duplicate look unique. Each sample gets at most16 attempts, then fails instead
of relaxing uniqueness. The canonical order is fixed seeds, train/validation/
test, sample index. Generation rebuilds this small global registry for every API
call, so call order or requested subset counts cannot reintroduce split overlap.
The executed corpus needed800attempts and rejected0duplicates; forced-collision
and exhaustion tests verify that rejection is bounded and cannot be bypassed.

## APIs

```python
from research.mamba3h.benchmarks.p1_positive import (
    generate, solve, model_view, model_numeric, encode_numeric,
)

ep = generate("mqar", 11, "train", 64)[0]
assert ep["targets"] == solve(ep)          # Offline only.
x = model_numeric(ep)                     # floats[L=6,D=8]
assert x == encode_numeric(ep, dim=8)
view = model_view(ep)                      # whitelisted current events/control
```

`generate(task,seed,split,count,**difficulty)` accepts only this fixed profile
and registered seeds/splits/counts. Optional difficulty keys are `length=6`,
`entities=4`, `values=4`, `writes=3`, `distractors=2`, `queries=1`. Changed or unknown
axes fail. Prefix requests return the same canonical examples as the full split.
`build_corpus()` returns `{(seed,split):list[episode]}` and sampling statistics.

Episodes include events/tokens/targets/query_mask/control and separate metadata.
Event fields are kind/entity/operator/value, with operator always None and value
None on QUERY/NOOP. The input boundary is `model_view(ep)`, not `**ep`.
Current control keys:kind/entity/write_id/revoke_id/write/read. Write is true only
on WRITE, read only on QUERY, revoke_id always-1. No target/value/address is in
control. Neris mapping:bool[B] write/read, long[B] entity, revoke_id ->
revoke_entity; optional retain/address are absent. Numeric x is observed input;
native/model-state keys and values must be projections before retrieval.

Independent `oracle.solve` scans only a query's past for the latest same-entity
WRITE. It imports no generator, online labeler or routing reference. It raises
`UnboundQuery` for an arbitrary query with no prior binding rather than reading
a future write or inventing a fifth class. Generated data always has a binding.

## Exact positive routing check

`routing.step(x[8],state,control=...)` is a CPU standard-library diagnostic,
not the Torch/native/model baseline. It copies current x's entity/value blocks
as preread key/value, reserves three slots, writes by current observed identity,
and queries exact dot-product top1 of occupied keys. No-read skips all similarity
work. NOOP never writes. There is no learned projector/readout or answer oracle.
Capacity overflow fails explicitly; no silent eviction occurs.

The harness `routing.retrieve(ep)` projects only label-free model input and resets
state per episode. Only the offline audit/test compares output with the independent
solver. Every generated example has exactly three writes, one read, three final
similarity comparisons and zero earlier comparisons. Logical reserved state
bytes216 (float64 key/value plus int64 identity) are a representation count, not
measured Python object RSS and not a native-memory budget comparison.
