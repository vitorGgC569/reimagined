# Training Dataset And Layer Audit Plan

The best dataset for verifying training is the NSOS curriculum, not WikiText by
itself.

## Dataset Decision

Primary training-verification dataset:

- deterministic curriculum generated by `OXN/nsos/scripts/nsos_curriculum_lib.py`
- smoke/pilot profiles in `OXN/nsos/scripts/train_curriculum.py`
- fixed holdout probes in `OXN/nsos/benchmarks/nsos_micro_suite.jsonl` and
  `OXN/nsos/benchmarks/nsos_eval_suite.jsonl`

Why this is the right first dataset:

- answers are exact and auditable
- phases isolate capability areas
- small enough for repeated CI/local runs
- covers algorithmic tasks, structured/circuit tasks, curated text,
  instructions, verifier labels, and memory recall
- failures can be traced to a phase instead of being hidden inside broad language
  loss

Secondary sanity datasets:

- `circuit_data/train.raw` for circuit memorization/generalization checks
- WikiText raw data for language/perplexity smoke only

WikiText should not be the primary correctness dataset. It is useful after the
model already proves it can learn exact supervised and structured tasks.

## Current Visibility Surface

Current observability-related code:

- `include/inspector.h`
- `include/nsos/inspector.h`
- `include/monitor.h`
- `src/health_monitor.cpp`
- `include/numerical_guard.h`
- HTTP `/metrics`
- `scripts/inspect_phase_responses.py`

This is useful, but not yet a complete per-layer audit system.

## Required Layer Audit Surface

The per-layer audit should capture, at minimum:

- layer index and block type: Mamba2, Attention, TTT, MoE/FFN
- input/output shape
- min, max, mean, standard deviation
- L2 norm and max absolute value
- NaN/Inf counts
- forward latency
- backward gradient norm when training
- MoE router top-k distribution and entropy when MoE is active
- tokenizer IDs and context truncation metadata
- RNG seed and determinism metadata

## End-To-End Audit Flow

1. Build a curriculum bundle.
2. Train with the `smoke` profile.
3. Emit layer audit snapshots at phase boundaries.
4. Evaluate `nsos_micro_suite.jsonl`.
5. Evaluate `nsos_eval_suite.jsonl`.
6. Save a model pack.
7. Reload the pack.
8. Re-run the same holdout probes.
9. Compare outputs, metrics, layer health, and determinism.

## Implementation Rule

Do not start by refactoring `jamba.cpp`. First add a narrow audit collector with
tests, then wire it into selected layer boundaries. Refactor only after audit
coverage exists.
